## Behavior and boundaries

Promote the tested bounded parser into a standard-library-only native core and
add a Linux profile lease using the original `.azlock` identity. Prove conflicts
with Java FileChannel locks in both directions, same-process acquisition failure,
release on normal exit and process death, and safe configuration save/recovery.

Writes require the lease, safe filenames, unchanged prior input, original
compatible `.saving`/`.bak` files, exclusive temp creation, fsync and atomic
rename. Preserve unknown fields and exact untouched bytes. No engine/native
resume format is written over Java state. No live user profile or torrent data.
Only write `native/`, migration records, and isolated `/tmp/biglybtc-*` outputs.

## Acceptance and handoff

- Core builds without Qt/engine/crypto under both pinned compilers.
- Existing Java/native format tests continue against the promoted implementation.
- Java/native lock and config round trips, interrupted saves and error cases.
- Record commands/results; source/native implementation stays uncommitted.
- This slice does not close all P01/P02 gates or operational profile parity.

Both compilers and the current Clang ASan/UBSan/LSan suite pass. The immutable
shared parser buffer survives document moves/copies and retains binary views.
For five synthetic 8MiB opaque-config loads, median process peak RSS decreased
from 28,300KiB to 20,112KiB. CPU/elapsed comparisons are noisy and this is not
a Java/native whole-client performance result. Test JVMs use two processors,
one batched recovery reader, explicit Debug initialization and bounded deadlines.
