# AD 001 Native engine integration

Status: selected for the bounded local P03 vertical slice; full engine parity,
resource comparison and release selection remain open.

## Evidence and scope

Use a libtorrent adapter for the standard local transfer slice. GCC/Clang
feasibility builds, Java-created v1/v2/hybrid metadata, partial `.az!` mapping,
corruption detection/repair and native resume/restart pass. Full source-built Java
receivers interoperate for all three variants; the reverse v1 direction and Java
v1 incomplete-file continuation also pass. These experiments use generated data,
owned loopback endpoints and disabled discovery/router mappings.

The development runtime is the independently hashed Ubuntu libtorrent2.0.12-1
package with Boost1.90. Inspected git source2.0.11 is a separate input, not falsely
the binary's exact source. A production source/build pin and patch audit remain
required. The bounded adapter must not depend on an installed Java application
or permanent JVM. The native core remains independent of the engine and Qt.

## Gap disposition before broader activation

| Behavior | Current evidence | Required integration |
| --- | --- | --- |
| v1/v2/hybrid metadata and standard TCP transfer | Original Java/native fixtures and peer tests pass | Expand malformed/multifile/magnet/protocol matrix |
| Original linear/incomplete payloads | `.az!` partial recheck/continuation in both engines | Original file-link/priorities/safe path mapping and completion behavior |
| Compact/reordered storage | Seven actual Java logical/control fixtures pass GCC and Clang mapping tests | Custom disk adapter, allocation/relocation/control writes and crash tests |
| Java profile/resume | Config/lock/codec/structured-edit/inventory proofs; state/cache writes testing | Translate original flags/blocks, cache coherence, flush and actual session switching |
| Queue/seeding/tag policy | Library exposes original startup/force/pause state | Port host policy; engine auto-management must not override imported intent |
| Mainline DHT/uTP/trackers/PEX/web seeds | Candidate library provides APIs; not qualified by local TCP tests | Source-specific fixes, wrapper integration, privacy and interoperability matrix |
| BiglyBT/Azureus DHT, AZ messaging and dependent services | Not supplied by Mainline DHT | Native source ports/engine hooks; never substitute a different DHT |
| I2P/Tor/bind/proxy/DNS/private isolation | Local experiments explicitly isolate traffic | AD-005 policy and verified adapters; no public fallback for unavailable private routes |
| Swarm merging/lightweight seeding/advanced statistics | Original sources inventoried, hooks not qualified | Host services or scoped engine changes with equivalent workloads |
| CPU/memory/release platforms | Limited diagnostic measurements only | Repeated equivalent Java/native workloads and full runtime/platform qualification |

The initial production-layout runner is explicitly an experimental local tool,
using a held shared profile lease and owned endpoint. It must reject layouts and
capabilities it cannot yet honor before payload mutation, rather than silently
resetting settings or starting a public swarm. These are pending implementations,
not accepted scope reductions. The complete user requirement remains seamless
same-file Java/native/Java operation with full functionality and better performance.

Porting the entire Java engine remains the alternative if required hooks cannot
be implemented economically/correctly. The current local results justify a
reversible adapter slice, not permanent acceptance of its unresolved gaps.
