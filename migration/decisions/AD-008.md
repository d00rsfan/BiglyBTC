# AD 008 Experimental native module boundary

Status: implemented bounded Linux LP64 development interface; production ABI and
release trust remain open. Extends AD-003's internal module architecture for the
user-authorized independent native plugin repositories.

Use one exported C entry point, ABI/structure-size/ID/version/capability checks,
fixed-width integers, borrowed request pointers and caller-owned result buffers.
No C++ STL, exceptions, Qt objects or allocator ownership cross the ABI. One host
owner serializes create/start/call/stop/destroy. Stop must drain work, destruction
must also handle failed creation/start, and code stays mapped until destruction.
The current modules create no workers or network services. Native code is trusted
in-process code; descriptor checks do not sandbox malicious libraries.

The Linux loader retains the selected file descriptor and maps that inode with
RTLD_NOW/RTLD_LOCAL. Reject writable-by-others, linked, nonregular or unowned
artifacts. The caller must authenticate the artifact before dlopen. Each update
uses a new immutable version directory; never edit or replace a loaded inode.
The ABI is experimental version1, not a stable public compatibility promise.

Country display-name localization is a synchronous host callback. The host owns
locale data/cache lifetime; a plugin must not initialize/unload a shared locale
library per instance or reset another service's global caches. The first sanitizer
run exposed allocations stranded by unloading ICU with the location module. The
host callback fixes ownership without suppressing leaks or pinning all modules.
Original country data remain in MMDB and flags remain loose images or JAR entries;
no Java plugin code executes to read a JAR resource.

An offline Python development store demonstrates signed Ed25519 manifest checks,
byte size/SHA256, original ID, ABI/platform, immutable version identity, activation
trial, fsync+atomic pointer, interrupted activation and rollback. It holds the
original `.azlock` and accepts only explicit generated `/tmp/biglybtc-*` profiles.
It is not installed in the app or enabled as an automatic updater. Production
requires descriptor-relative traversal throughout, host lease reuse, catalogue
expiry/replay/transport policy, key authority/rotation, and dependency closure.
Only ephemeral test keys are generated; no production trust root is invented.

Keep a monotonic highest accepted sequence when rolling back. Java configuration,
descriptor, JAR, database and directory case remain untouched. Original Java JAR
selection and bencode decoding are checked before/after native changes with the
frozen source-built core and ReferenceFence. Never initialize a normal Java plugin.

SpeedScheduler's module returns commands and rate changes from caller-supplied
host snapshots. The host must acknowledge actual pause/resume and persist ownership
before claiming integration. Its source redistribution grant remains unresolved;
local qualification does not authorize publishing uncertain upstream content.
mlDHT host policy is an internal static module until its network/session service
exists; do not advertise an operational DHT capability from a policy-only port.
