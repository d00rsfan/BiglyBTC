# AD 003 Execution and internal extension foundation

Status: selected for bounded runtime implementation; integration/concurrency
evidence is required before closing the full decision.

## Scope and source

Use internal build-time modules, a shared core for GUI/headless composition, and
explicit lifecycle calls. No cross-version C++/Qt plugin ABI or permanent JVM.
Plugin IDs remain compatible and native project names use BiglyBTC prefixes.
Reference ownership/execution behavior: AsyncDispatcher, AEThread2 and plugin
lifecycle interfaces at `cb8c6cb9bb97916cbc7e80338a017200ffc3e71f`.

Each mutable service belongs to one executor. Commands use stable IDs and
generation validation in the owning service; widgets receive immutable/batched
snapshots. Configuration IO cannot call widgets. Start workers explicitly after
dependencies/configuration are ready; do not start hidden services from static
initializers. The captured Java configuration/Debug/RootUpdater initialization
deadlock is a regression case to avoid, not a required behavior to preserve.

## Bounded executor contract

Use C++23 `std::move_only_function`, `std::expected`, RAII `std::jthread`, standard
futures, stop sources and condition-variable waiting. Qualify the newly used
facilities on both pinned compilers through behavior tests. One worker owns each
executor's tasks. Its bounded queue rejects overload explicitly before accepting
a command; the caller retains responsibility for retry/reporting. No accepted
control command disappears: it completes, fails, or returns cancellation.

Cancellation is cooperative. Queued cancellation is observed at dispatch;
shutdown promptly resolves queued commands as cancelled and signals the active
command. Stop callbacks run without the queue mutex held. Shutdown can be
requested from a callback; ownership/destruction and joining belong to an outside
host thread. Tasks must not destroy their own executor or wait for a queued task
on the same executor. Deadlines and bounded operation-specific buffers remain
service responsibilities. The queue limit excludes one executing command.

## Alternatives and integration gates

An unbounded general thread pool hides ownership and overload; a shared-pointer
object graph obscures lifetimes. A single application-wide worker would serialize
unrelated disk/network work. Use explicit per-service executors, with the final
count established by measured workloads. The core runtime has no Qt dependency.

Before full AD-003 closure, integrate real services, test cross-service shutdown
order, bounded telemetry/coalescing, cancellation and persistence acknowledgments,
and qualify TSan. Self review is available; no independent reviewer is assumed.
The initial core runtime is reversible without changing persistent formats.
