Service surface

Link biglybtc_rss_document and include rss_document.hpp. Call
biglybtc::search::parseRssDocument(QByteArray, RssContext, RssLimits), returning
std::expected<RssDocument,RssError>. The library depends only on QtCore and
C++23. The production implementation has no file, network, profile, engine,
Host, timer or plugin operation. It owns the XML, strings, results and issues;
no views into a parser, caller buffer or asynchronous producer escape.

RssContext.rootPage and basePage are the exact original WebResult reconstruction
prefixes. They are not a fetch base or a QUrl resolution request. RSS channel
link concatenation, root/base string concatenation, raw-versus-reconstructed
nested link decisions and ordered enclosure/Atom/Vuze overrides remain as
reviewed. All result URLs precede Engine.adjustLink and remain untrusted data.
The module does not determine whether a URL may be fetched or a result imported.

Values and uncertainty

Preserve immediate TEXT/CDATA and first matching child semantics, Java trim,
HTML40 title conversion, item/channel order, GUID/Atom ID, raw publication
text, binary-unit size setters, explicit peer counts and tracker priority.
The251-entry HTML40 table and all value implementation/test bytes are unchanged.
Raw32 hash setter text remains distinct from canonical ASCII Base32/40hex
conversion and canonical magnet synthesis. No full32 torrent identity or
download-manager restore claim follows from RSS hash text.

Missing counts/sizes stay absent rather than acquiring a zero fact. Issues are
structured field/channel/item diagnostics; XML itself must not be logged.
Relevant unresolved HEAD decisions withhold torrentLink and any dependent final
detailsLink; a later unconditional setter may settle the value. No HEAD answer
or cached engine state is invented. Unsupported title-magnet/description
heuristics remain diagnosed. A declared auto-download boolean is data only.
publicationText is raw text: no epoch, timezone, assetdate or date-parity claim.

Bounds and lifecycle

Default ceilings are4MiB input,32768 element/attribute nodes,64 nesting levels,
4096 items,65536 UTF16 units per field,2Mi UTF16 units in parsed text and
separately2Mi in exported result text, and16384 issues. Caller limits may only
lower these ceilings. Oversized input/context, exceeded counters and malformed
XML return an error; allocation failure returns Memory. These are logical
document quotas, not a measured peak-RSS or CPU deadline guarantee. Channel
count is bounded through the node ceiling. Namespace declarations and Qt's own
parser allocations are not separately charged as attribute nodes.

DOCTYPE/entity-reference tokens are rejected before a resolver or provider is
consulted. No external file/URL resolver is installed. This conservative XML
boundary is intentional; it is not full original permissive XML parity.

The call is synchronous with no thread, callback or retained work. It has no
mid-call cancellation token or worker join receipt. Later consumers must bound
the delivered body before calling, limit queued/in-flight documents, invoke it
off the UI/event loop where needed, and discard completed values when their
own source/request generation is cancelled. Cancellation/source revocation,
aggregate quotas and joins belong to that future consumer, remain unqualified
here, and must not be inferred from parser bounds. No worker is added by this
integration. Caller ownership of permission and source lifetime is unchanged.
