PROPOSAL ONLY — P06 profile I/O, no implementation or execution

Use the existing core::Executor unchanged, with one private instance per explicit OwnedAzureusService. Its capacity covers QUEUED work only: separately cap8 service operation slots across queued/active/ready work and64 total pending datagrams/outcomes (datagrams<=1400B, values<=512B). One I/O job per operation validates a fixed batch cut captured BEFORE its reads; later fragments need the next cut. This accommodates bounded streams without64 concurrent disk jobs. Do not borrow SessionBridge::worker_: its finalizer destroys/joins services, so queued work on it could deadlock service destruction.

Move startup preflight, normal receiving profile checks, publication next()/fsync and rating begin/continuation/passive source reads onto that executor. Keep existing version-file bytes, unknown fields, signed32/chunk128 math, CAS/recovery/poisoning and consumed reservations unchanged. Jobs retain the SAME OFD alias, expected source revision, owner generation, exact operation/batch identity and absolute deadline. Results own their data in fixed slots; one coalesced Qt wake drains them. No network-thread disk read, future wait, raw Owner capture on the I/O worker, unbounded callback queue or new polling timer.

Freshness needs a narrow shared source gate, not a cached validation Boolean. Extend the existing ProfileLease acquisition lineage with a cooperative gate/revision; retained aliases share it, independent/replaced lock acquisitions do not. Relevant ConfigFile create/save, TorrentState write entry points and version-file mutations take it BEFORE effects. Retain version-manager serialization/CAS, with gate→version-mutex lock order. The I/O worker holds the gate from source validation through single-use actor acknowledgement; native writers cannot change the checked source between those steps. The worker acquires/releases its own lock; never transfer a mutex lock between threads. Generation-only checks would miss a write immediately after their check. Hostile external atomic pathname swaps remain outside this cooperative guarantee, as today; retain held-FD/path/CAS checks and state the limitation explicitly.

A Pending→Executing permit binds only that operation/batch. The network owner consumes it once and rechecks CURRENT owner/request generation, stop/cancel, deadline, actual socket/peer admission, token, router/closest and DB facts. Those network facts are never minted by disk validation. It performs only bounded network/DB work, then acknowledges. Stale/cancelled/expired Pending permits cannot send/store. Failed result delivery revokes rather than grants. Stop wins at final locked success publication. Incoming FIND_NODE/token, STORE and FIND_VALUE need bounded suspend/resume; outgoing publish/read/rating use permits at their existing fences. No profile permit is reusable for subsequent packets. No new Host/public activation or connectivity authority.

Close seals stop/generation, revokes Pending permits, closes sockets and resolves network deadlines/commands, and acknowledges already executing bounded actor work. The external lifetime joins the network owner and cancels/joins the I/O executor; aliases/mailbox outlive both. No finalizer waits on itself. A blocked kernel read/fsync cannot be forcibly cancelled: socket/deadline shutdown can progress while disk is held, but synchronous close() must still wait for the syscall to return. Measure and report that distinction; do not promise bounded syscall/join latency. Passive rating values withdraw on a cooperative source revision change or later failed external-source check; returned immutable observations remain historical.

Actual barrier tests: hold a real read/reservation through an existing observer/injected I/O boundary while unrelated owned PING, RPC deadline, cancel and socket-close still progress; then release and prove real STORE/readback. Exercise source edits before permit execution, lock/profile/version replacement, stale-generation delivery, close/cancel before completion and slot overflow. Verify no stale send/STORE/current values, source-I/O thread IDs, bounded queue high-water and unchanged CAS/indeterminate/wrap/recovery behavior. Reuse existing field/version compatibility proof; no Java replay. Public/performance qualification stays open until actual progress/resource evidence passes.

Expected production scope: shared ProfileLease/control and relevant profile/state writer guards; AzureusValueVersions; OwnedAzureusService and its local-publish/rating includes; OwnedPingTransport suspend/resume. Core Executor unchanged; no provider/UI/default-policy work. Architecture approval precedes implementation.
