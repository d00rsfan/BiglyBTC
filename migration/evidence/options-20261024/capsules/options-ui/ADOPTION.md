# Options dialog handoff

Source-only UI component and focused Qt tests; no author builds or executions. Install the four files from staging/ into preview/native/. Add options_presentation.hpp, options_dialog.hpp and options_dialog.cpp to biglybtc_ui. New test target: biglybtc-options-dialog-tests, AUTOMOC, link biglybtc_ui and Qt6::Test; CTest name options-dialog, QT_QPA_PLATFORM=offscreen, explicit timeout 120. No storage/engine dependency is added to this component.

API: OptionsDialog(QWidget*); beginSession(nonzero monotonically increasing session) before show; invalidateSession() after the caller has resolved dirty-close policy; setBusy(bool); setSnapshot(OptionsPresentation)/setSaveResult(OptionsSavePresentation) return admission bool. loadRequested(OptionsRequest) and saveRequested(OptionsSubmission) are value-owned signals. Register all four declared metatypes for queued connections.

Read packet: matching active session/request, complete valid OptionsValues, nonzero revision. Failed read: null snapshot and bounded failure. OptionsValues translates the adapter's five field states without passing a Document/lease into Qt. OutOfRange Boolean integer 2 stays an indeterminate checkbox until explicitly edited. Undecodable saved strings are shown decoded but untouched fields are never submitted or auto-dirtied.

Save submission carries only changed fields and the original loaded revision. Failed result has saved=false, matching original session/request/revision, and optional failure. Success has saved=true, same outer original tags, actual cumulative restartRequired, and a complete nested OptionsPacket using the save session/request with a strictly newer committed revision. Replies never infer save success from worker idle. Root must send explicit failure if dispatch rejects/throws/cancels. Root owns cross-field policy validation, engine application and revision/CAS storage ownership.

Apply remains open; OK closes only after matching save success; failure retains edits/revision. Saving disables editors and blocks close. Dirty close offers Save/Discard/Cancel. Clean close invalidates pending read tags; profile invalidation clears credential text and draft. Signals, field rendering, action updates and callbacks use lifetime/revision guards. Password editors are masked; dynamic status text is plain and bounded. Classic tree: Connection with Advanced/Proxy children, Transfer, Queue, Files. Scrollable forms fit smaller windows. Unsupported controls stay available for explicit repairs and are visibly marked saved-only.

Optional test capture: BIGLYBTC_OPTIONS_CAPTURE_DIRECTORY absolute owned directory; writes options-connection.png and options-proxy.png from the loaded offscreen dialog. This provides no compositor/user-acceptance credit. Twelve behavioral methods cover topology/masking, deferred read, stale/malformed packets, sparse invalid/raw fields, revert, validation, conflict/retry, commit-close, dirty choices, read retry/credential clearing, deletion at request signals, and same-window profile reentry. Actual rows/results are for the root's single cohesive run.
