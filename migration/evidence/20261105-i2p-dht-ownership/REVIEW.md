# DHT teardown stays within its channel epoch

An Actor that never acquired a DHT scope used to disable another owner's scope on close/destruction. An older Actor could also disable a separately installed replacement scope. Teardown now supplies the exact owned epoch; the channel compares its raw epoch before clearing it, including when source/lease revocation makes the current observation zero. Existing manual teardown, source checks, receive limits and final socket-write fences remain unchanged.

The two new channel regressions exercise unused/rejected Actor close/destruction and stale Actor close after scope replacement. All ten channel test results pass with GCC and leak-enabled ASan/UBSan. Each lane compiled the three affected translation units once against frozen read-only dependencies. The initial GCC run could not open loopback sockets in the Codex sandbox; its exact image was rerun in the authorised ordinary-user context. No privileged helper, real profile or running Java application was used.

The immutable implementation commit is recorded by the subsequent provenance commit in upstreams.lock.json and IMPLEMENTATION.json. Source baseline, four changed source digests, independent source review, exact qualified image digests and compact test logs accompany this review. The normal CMake reproduction target is biglybtc-i2p-dht-channel-tests; CTest name i2p-dht-channel. This is an ownership correction, not evidence that incoming server mode, cold I2P discovery, the whole P07 phase or client parity has completed. The prepared diagnostic7 inputs remain frozen and await the separately required normal-terminal OS action.
