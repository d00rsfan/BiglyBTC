# Independent Executor finalizer review

No blocking issue was found in the isolated frozen draft. This is a static source/lifetime review, not a C++ parser, compiler, runtime, race-detector or sanitizer result. No build, test, JVM, native process or allocation injector was executed. Only these two review artifacts were added; all 37 protected draft/base/stdlib fingerprints remain unchanged.

The reviewed manifest is `4c46f61dfdc117028551ee3db3886e562ebdc7178b69689d4acdfa3cbff8640c`; implementation.patch is `f6743a450b49f39cbd5771bed2ae7c179366b41e770c340c598305354e616946`. Applying all four unified patch sections in memory exactly reproduces the isolated header/source and two new tests. The original executor test is byte-identical (`41b8ac27f40d257a199e03d48865cd32a7a8f91b5a655a7f94a2a1f7c5ac9ea4`). All nine main/base sources still match their pre-draft pins. The original out-of-line start() API delegates to the new overload without changing ordinary operation/result/queue behavior.

Startup ownership is sound by inspection. The rollback callable is declared before the unique_lock. Rejection destroys the lock before the caller's supplied parameter capture. Thread-construction failure moves the owned hook out of the member, explicitly unlocks, and rethrows before caller-local capture destruction. Moving the noexcept move-only callable does not introduce an allocating copy. started_ and accepting_ commit only after constructing/moving the new jthread; that worker must acquire the same mutex before reading admission. A failed startup therefore retains an unstarted, retryable owner unless a concurrent/reentrant caller has separately stopped or started it. The construction path never replaces an existing joinable worker in an admitted startup.

The shutdown barrier covers the previously identified accepted-work cleanup race. Each shutdown caller registers its cleanup under the mutex before publishing stopped admission and detaching queued Work. The cleanup guard is declared before the detached deque and active stop-source copy, so its destructor unregisters after those records have been destroyed, including during ordinary unwinding. Queue operations release their callable before satisfying the cancellation promise. Active operations release their callable, reset active_ and satisfy their completion promise before the worker proceeds to its final wait. The worker waits on the cleanup predicate without its already-cancelled stop token; a cancelled token or spurious wake cannot bypass the predicate.

Stop requests, user callback/capture cleanup, finalizer invocation and finalizer capture destruction all occur without the Executor mutex. Nested shutdown therefore need not wait for another caller's cleanup and cannot self-deadlock on that mutex. Once the count is zero, no accepted queued Work remains available to a later stopped caller. The finalizer runs once outside queue capacity/cancellation, then its callable is explicitly cleared on the worker. Host join covers both invocation and capture destruction. Synchronous stop callback reentry into pending/submit/shutdown and the worker-initiated shutdown sequence retain the original returned-operation result semantics.

The lifetime restriction is necessary and documented. The cleanup counter is not an ownership lease: decrementing it does not make an external requestShutdown caller's later notify safe against simultaneous object destruction. The host must exclude/quiesce ordinary external calls before starting destruction. Worker/finalizer reentry during the host's join remains valid because those members outlive that worker. Self-destruction is unsupported. A blocked operation, stop callback, capture destructor or finalizer can still prevent completion; no deadline or graceful persistence outcome is supplied by this foundation hook. Existing possible allocation failure in constructing the local cancellation deque is not newly removed or tested by this change.

All six new gated cases are present and called from the new finalizer test's main, with one separate startup case and exactly three CTest entries. The tests exercise legacy/empty/rejected/pre-stopped startup, full queue and cancellation, normal/throwing work, blocked queued capture destruction, concurrent/reentrant shutdown, worker shutdown, ready accepted futures before finalization and join blocked on finalizer capture destruction. Gates use predicates/promises with finite failure waits and no sleeps. Read/write publication of non-atomic thread IDs and ticket vectors is ordered by gate/future synchronization or same-worker execution. The finalizer/capture assertions inspect the ordering at the actual ownership boundary rather than only checking eventual main-thread results. The original test and assertions remain unchanged.

The deterministic startup injector is appropriately isolated to its own executable. Hook/capture construction precedes arming the initiating thread's one-shot ordinary operator-new replacement. The qualified jthread constructor initializes its stop_source member before its thread member; that stop_source's exact original helper allocates its stop state. All three current qualified standard-library headers and copied header bytes match their pinned hashes, and all four proof fragments match verbatim. No earlier allocating operation is introduced by the supplied start path. The prepared assertions identify the dedicated injected exception, initiating thread, moved hook, no invocation, unlocked caller cleanup, NotStarted and successful retry. This characterizes pre-thread stop-state allocation failure; it does not inject or claim OS thread exhaustion. Alignment/allocation behavior elsewhere is not tested by that one-shot replacement.

Root still needs actual GCC/Clang and sanitizer execution, with the startup allocation replacement confined to its dedicated executable and TSan qualified separately if its runtime is usable. No Java equality, persistent-session integration, compatible Close/pause/resume, storage release, durable resume, completion publication, lease ownership or performance result is implied by this review.
