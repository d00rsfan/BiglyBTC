# Independent general-room owner milestone

Two independent Native clients discover one another via an actual owned Azureus DHT seed using FIND_VALUE, fresh token acquisition and STORE. They exchange signed/encrypted Unicode messages through their existing SDK UDP listeners, and saved history is restored after the worker joins. No direct peer/UID injection establishes room membership. The Source policy validates the same profile OFD, relevant networking fields, actual SDK listener and each saved room identity; unrelated statistics/nickname edits remain compatible. History writes bind the original identity, primary source and current save choice. Stale nickname editors cannot change a different nickname scope.

The bounded worker serves both address families, schedules crypto after source release, uses six exchanges per room, retains original favourites/nickname/history formats and stops/revokes its attachment before engine/profile release. Community and View expose an independent Public Chat Rooms tab with shared/per-room nickname selection. Actual SDK address discovery requires matching correlated reports from two different node IPs. The owned tests qualify IPv4/IPv6 transport; the complete two-room-owner discovery test is IPv4.

The new Public-only SDK source/image verifier passes offline. The bound app cohort and full original Java room-handler exchange remain open: this milestone is not complete operational-chat or whole-component parity. No real profile/room has been opened or posted to. No fresh sanitizer result is claimed. The protected daily-use candidate and its installed provider remain unchanged.

Initial fixture failures and fixes are retained locally: raw permission alone did not attach a routed seed contact; generated config fields needed dictionary insertion rather than updating absent keys; disabled history deliberately had no writable preimage. The production guards correctly refused each invalid setup. A separate real Native same-IP node-ID collision bug was fixed so a valid ping gets a reply without admitting a duplicate local routing ID.
