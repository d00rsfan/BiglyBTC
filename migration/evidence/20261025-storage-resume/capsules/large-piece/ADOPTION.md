# 128/256 MiB original piece geometry

Source-only amendment against exact current CF01 native working files, HEAD `b44ec22ebb3dbb6cee3ade23c32a7ad26a373926`. Copy eight staged paths or apply `large-piece.patch`; both SDK and desktop core header/implementation pairs are byte-identical. Add `tests.cmake.fragment` to the existing physical-IO test target (two additional linker wrappers; existing ftruncate wrapper/timeout remain).

`compat::OriginalMaximumPieceLength` is 256 MiB. Original cb8 `TOTorrentFactory.STANDARD_PIECE_SIZES` includes 128/256 MiB. The pinned LT metadata reader accepts up to `(32767 * 16384)` bytes, approximately 512 MiB, so these existing original sizes fit. LT **creation** independently caps new pieces at 128 MiB; creation is unchanged. Shared originalLayout and nonlinear IO use the same new constant. Linear IO, request limit 64 MiB, one-million reordered slots, controls, descriptor and file bounds are unchanged. This does not admit every LT-supported nonstandard size.

Compact→linear now copies in at most 64 KiB scratch chunks. Its destination lies outside the entire packed source (identical ranges need no copy); each read retains descriptor identity checks. EOF is captured before self-expansion so a sparse short tail does not become artificial additional input during that invocation. Read/write failure fences the object. Old packed bytes/control stay intact, final truncate/fsync still precede successful return, and caller-owned conversion journal→storeL→control retirement ordering remains unchanged. Replay after partial expansion may scan the bounded full packed tail because the old journal does not record pre-expansion EOF; memory remains 64 KiB and original known bytes remain intact. No new completeness/durability claim or hidden control extension is introduced.

Existing eight physical-IO families and old small layouts remain. The prior rejection check moves from newly supported 128 MiB to 256 MiB+1. Three new families use sparse 128/256 MiB geometry with tiny actual writes, C/R/X boundary fragments/reopen/missing ranges, a huge nominal but short physical compact tail, and targeted real pwrite failures before/after the first chunk with authenticated replay. Pread/pwrite wrappers assert real ≤64 KiB copy requests; no full huge-piece buffer/transfer is used. Core geometry adds raw-preserving 64/128/256 MiB and v2 padding checks plus upper-bound rejection.

No builds, C++/Java execution, native mutation or source qualification was performed by the author. Root owns the combined source/runtime qualification. Source ranges and full leaf hashes are in `source-pins.json`.
