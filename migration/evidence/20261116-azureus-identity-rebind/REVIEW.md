# Automatic Azureus transport and local-identity rebinding

Native source `350f1bd142716d4e9f0e564a0af7cb6b21bcc707`, tree `9d467c86798a040cabeee47b96b186eb78977acc`; original upstream

The normal owner processes only the actor's correlated address claims through
fresh source gates and the qualified original30s/five/ten-minute policy. A claim
never becomes an advertised address. The existing shared-socket probe must obtain
two matching correlated observations from different reporter IPs. Its confirmed
change schedules retirement outside the provider's callback stack. This retains
the stricter existing native confirmation rule; original single-report/public-
address fallback is not claimed. Owned same-host interfaces are not public WAN
or NAT evidence.

Actual listener withdrawal, replacement or saved-policy rejection reconnects the
network instead of stopping the entire chat service. A source-worker read supplies
the configured port; reattachment cannot silently fall back to a withdrawn socket.
The owner does not reconfigure the SDK: a changed SDK listener and compatible
saved configuration are prerequisites. Normal binding refresh remains30s; the
short generated-fixture interval is available only through the owned factory.
A newly available IPv6 listener creates its proper network3 lane; the owned
factory's earlier network4-for-IPv6 selection is corrected. Both owned attach
paths recheck actual loopback bindings.

A network generation fences all prepared source operations. Old callbacks are
revoked/failed while their lane objects still exist; replacement slots are used
only after the source frames and post-release work drain. Actor queries, surveys,
cached forwarding, token state, NAT, pending lookups and publications are retired.
Signed room cores, keys, read state and message history remain in memory, including
rooms without saved history. New room sessions explicitly replace old mappings.
Torrent and rating source ownership is preserved and revalidated before effects.
Observed provider overrides are discarded when their actual binding disappears.

The volatile database survives a transport replacement. Original mapping local
values are removed under their old ID, updated in place and reinserted with the
new originator and sender. Creation/store times, payloads, versions, flags and
lifetime remain unchanged except original same-version collision reset rules.
Remote values and mapping identities survive. Old cache/survey cycles and removal
receipts are invalid; a partial mutation failure closes the DB. Actual Java
DHTDBMapping.updateLocalContact supplies seven comparisons, including newer/equal
remote-version collisions. Another actual Java setControl/queryStore experiment
confirms that an existing prefix-index collision winner is retained on ID change;
the native owner preserves it too.

Every real transport replacement purges direct signed key blocks before recording
its address and before binding the new actor, even if its host IP stayed the same
or optional address history is unreadable. The earlier cold-start cache behaviour
is retained. Actual profile tests cover healthy/unreadable same-host replacement,
stale preimages and publication ordering. Generated official-shape signatures
use explicit owned test roots; public production retains the official verifier.

Actual normal-profile SDK tests change the bound IPv4 address, preserve and read
a previously stored remote value from the new socket, retain an unsaved chat
transcript, install a fresh signed block, then change the configured/bound port
and prove that the direct block was purged. They also add a real IPv6 listener and
obtain a network3 reply, and stop promptly with the listener absent. IPv6 fixture
ports use distinct original modulo8 node-ID slots. No seeded/address facts are
injected into the owner. Initial test API/clock/completion/IPv6 setup failures
are excluded; accepted groups are recorded in qualification.json.

One coherent GCC16 Release/C++23/Qt6.12.0 application link and the affected normal
identity/key-block/query/survey, chat/torrent privacy, related-content/rating and
wire checks qualify this integration. Unchanged controls and storage checks from
the previous chapter are not replayed or presented as fresh evidence. No live
profile, payload, running client, protected SDK or current daily was modified.
No new preview/rollback image was collected. Real WAN/NAT hot-change acceptance,
complete original routing/transport/settings coverage and full F09 parity remain
explicit follow-ups; this selected runtime-rebind chapter is not that broad claim.
