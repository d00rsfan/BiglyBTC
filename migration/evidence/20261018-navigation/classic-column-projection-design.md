# P04-10: owned classic column-layout facts

This first stage is a pure, projection-only capability. `readColumnLayouts(const Document&, ColumnLayoutLimits)` returns an owned result or fixed `ColumnLayoutError`; it does not read files, apply layouts, resolve aliases, normalize registered-column state, migrate keys or write anything. Upstream is `BiglySoftware/BiglyBT@cb8c6cb9bb97916cbc7e80338a017200ffc3e71f`; source authority and 60 complete method hashes remain in the unchanged [persistence audit](classic-column-persistence-audit.json). The native starting commit is `03e31e5ce260e1327e63cca63d22d8d5984ceae9`. The header is the only new native file in this design phase.

## Ownership, bounds and errors

The input is a const `Document`, but the output does not alias its mutable tree. Validate lower-only configured limits, raw input length, and the input tree with an iterative bounded walk before serialization, recursive comparison or copying. Enforce ordinary core maxima even when the caller originally parsed with larger quotas: 4 MiB input and per-string caps, 100,000 nodes, root depth 0 through maximum depth 64. Check the next node/depth/count before visiting descendants; detect changed/origin markers and malformed tree shape without an unbounded recursive walk. No serialization is necessary.

Then copy original bytes once and parse them into a new bounded owned `Document`. Compare the supplied tree against this bounded parse with bounded iterative traversal: node type, integer/byte identity, child count/order and source begin/end must match, and edit/origin markers must remain absent. For byte nodes compare their expected original-buffer span/length before reading bytes, rather than dereferencing an untrusted replacement view. This catches ordinary edits and raw/tree inconsistency without accepting a modified tree merely because old bytes remain parseable. A successful result owns `shared_ptr<const Document>` over the fresh parse; projected ID strings own bounded copies and no result pointer/view borrows from the caller. Later caller edits, copies, moves or destruction cannot alter it.

This deliberately costs one additional input-sized raw byte allocation and a second bounded parse/tree, plus bounded projected vectors/IDs. Unknown table/plugin/userData/tail subtrees remain only in that one owned document, not cloned into every record. This is a structural allocation bound, not a stack, allocator-overhead or RSS claim. The caller's pre-existing document is outside result ownership. Failed allocation returns `Memory`; count/byte/depth/issue excess or an attempt to raise any limit returns `Limit`; edited/inconsistent input returns `EditedDocument`; an otherwise bounded unedited non-dictionary root returns `Root`. Unexpected non-limit parse inconsistency returns `EditedDocument`. No successful truncation or partly populated result escapes.

The document limits are checked first (configured caps, raw size, then bounded tree validation); root/type and fresh consistency checks precede projection. Selected-table counts and ID lengths are preflighted before their record allocations; issue capacity is checked before each issue. Limits are 1,024 `Column.*` records per selected pane (including malformed records), 32 selected sort slots per pane (including duplicate/malformed IDs), 256 bytes per projected ID and 4,096 total issues. Only reductions are accepted. Unselected opaque tables/fields are bounded by document limits alone. The existing parser's duplicate-dictionary rejection remains explicit; duplicate list/sort entries remain representable.

## Table and field contract

Only exact `Table.MyTorrents` and `Table.MySeeders` are projected. Missing exact table permits matching `TableDefault.MyTorrents` / `TableDefault.MySeeders`. Present empty exact maps win; wrong-type exact maps record `ExactTable` plus `WrongType` and do not fall back. A selected wrong-type default records `UserDefault` plus `WrongType`. Both absent means `Absent`/`Missing`. Unused defaults, scoped `::` tables and modern `.big`/`.small` tables are untouched raw content. Native members `incomplete` and `complete` are identities, not registry decisions.

Each `Column.*` entry is retained in source dictionary order, with its dictionary-pair index and exact unnormalized suffix. Prefix recognition alone sets `hasColumnSettings`, even for empty IDs or non-list values, matching the source manager's key test. A non-list entry records `WrongType`; its individual slots are Missing, as the original loadSettings substitutes an empty list. No original all-visible/reset/integrity action runs.

List positions are 0 visibility, **1 position, 2 width**, 3 tooltip, 4 sort direction, 5 userData, 6 alignment, 7 foreground RGB, 8 background RGB and 9 icon enable. Integer facts retain raw signed64 plus defined signed-low32. Missing and wrong-type slots stay separate. RGB must be a list of exactly three integers; wrong outer type is `WrongType`, bad length/member is `Malformed`; members retain raw64/low32 when the whole triplet is valid. UserData and last.reset expose only presence/type; their values remain raw. Other unknown fields/tails remain raw.

`visible`, `automaticTooltip`, `iconReferenceEnabled` and `direction` are **decoded requested slot facts**, not effective Java properties. Numeric false is known false. Visibility/tooltip mean low32 exactly 1; icon means low32 nonzero; sort direction is known only for low32 >= 0 (1 ascending, other nonnegative descending). Negative sort order retains a known number but unknown initialized direction. No inherited/default direction, width clamp, registry position assignment or visibility normalization is invented.

The three per-column legacy flags are exact: `legacyPositionRequired` is true iff position is Missing/WrongType; width and tooltip use the same rule for their respective slots. A present negative numeric width still has `legacyWidthRequired=false` because the source calls setWidthPX and may ignore it without consulting legacy config. A non-list record needs all three legacy lookups. No lookup is performed. Missing fields and unresolved fallback are presence/flags, not one diagnostic each; malformed shapes/types produce fixed issues. Empty/NUL/invalid-UTF8 IDs remain owned bytes plus factual flags/diagnostics, never normalized or dropped.

## Sort precedence and exclusions

A valid `SortColumns` **list** always wins, including an empty list or a list with wrong-type/empty/duplicate members. The list's presence remains Present; individual malformed IDs are retained with their own presence and source index, and the original order is unchanged. Over-limit lists fail with Limit, not legacy fallback. The reader performs no painted-view `#` fallback for an empty list.

Only an absent or wrong-type `SortColumns` value permits the legacy `SortColumn` singleton. A byte string there selects `SortColumn`, including empty bytes; otherwise `LegacyGlobalRequired` records that original global fallback is unresolved. Preserve `sortColumnsPresence` and `sortColumnPresence` separately. Current-list IDs have source explicit UTF-8 interpretation; legacy singleton bytes use unspecified JVM default charset. `validUtf8` is only a byte fact for legacy data, not a resolved JVM decoding or source rejection; do not emit an Encoding issue solely for non-UTF8 legacy singleton bytes. No multi-sort or Qt row sorting is applied.

Original global fallback contains `if (s != null || s.isEmpty())`, which has a null-guard hazard before it removes old keys. This stage neither reads that global value nor repairs/emulates the hazard; `LegacyGlobalRequired` expresses the unexecuted boundary. Original malformed RGB/map faults can occur after partial state changes; the native projection instead diagnoses each field independently and has zero credit for callback/registry/default/partial-effect behavior.

## Independent test plan and next gate

Freeze the API before implementation, then use generated bencoded documents to test both exact tables/default provenance, empty versus malformed, all slot positions/low32 extremes/known false, legacy flags including negative width, valid-empty/malformed-member sort precedence, raw unknown/plugin/userData/tail retention, malformed maps/RGB/IDs, every lowered cap and edited/higher-quota inputs. Ownership tests must destroy/edit the caller and retain/move/copy results. Include a deep caller document admitted under larger quotas to prove rejection before unbounded traversal, plus a same-length edit to prevent old-raw reparse acceptance.

All compatibility reader/Bridge/UI/Qt geometry/sort/reset/writer work remains outside P04-10. Root must approve the frozen header/design before authoring a `.cpp`; no CMake or test registration changes occur here. No Java runtime, profile read, source equality or native runtime claim is made.
