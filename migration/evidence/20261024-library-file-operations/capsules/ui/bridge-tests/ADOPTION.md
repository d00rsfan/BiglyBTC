# Actual file-operation/creation Bridge boundary tests

One new test source; copy its staged path and append CMake.snippet. Requires the
approved bound runtime, real desktop Host, profile/storage and actual creator.
No synthetic engine status/producer packets, no Java/original profile, no public
network. Reuses OwnedEngineFixture, its actual numeric TCP peer and fixed source
metainfo; all mutable paths are private QTemporaryDir roots.

Six behavioral methods are authored (creation has explicit true/false import
rows). Actual Qt row/assertion/pass counts are unobserved. No compiler or target
has been run by the author for this capsule.

Live preview is delivered through the actual FileOperationDialog so its private
copy must execute. Exact state/inventory bytes AND inodes are unchanged by
preview, and actual transfer continues afterward. Paused move must retain pause,
old cumulative byte bases, original partial RECHECK flags and exact payload
inodes, with no partfile conversion. Stopped relink preserves the source; Delete
without confirmation preserves files; fresh confirmed Delete removes only the
new mapping. Altered displayed paths and stale library revisions fail before
any state/payload mutation. Actual creation uses root's creator with source-byte
preservation, metadata parse/hash, explicit stopped-only import, wrong-token
cancel refusal and no overwrite. Actual Window create/result routing allows its
finished callback to delete the Window while Bridge finishes and releases lease.

Required source fixes discovered during authoring and owned by root:
* Compare the GUI's copied plan by all presented value fields against worker
  cache; shared_ptr identity is deliberately different.
* Host::accepts must validate the old UI Target before any execute-side effect;
  post-stop reprepare may tolerate only incidental checkpoint fields.
* Window must guard member access after dialog setters and invalidate/show/
  raise/activate calls that can synchronously delete or rebind its objects.
* Isolated paused readmission needs the same stop_when_ready disk-check guard
  even without a whole queue policy. Keep its real regression assertion; do not
  weaken it to a saved-text pause or accept restart failure as success.

There is no deterministic pre-publication cancellation gate in this fixture;
wrong-identity cancellation is tested, while actual cancel outcome ordering is
covered in dialog tests and creator's own stage/stop-token tests. No causal
cancellation or whole Java runtime equality credit is claimed here.
