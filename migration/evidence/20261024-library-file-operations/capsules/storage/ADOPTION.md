Worker-only file operations

API: prepareFileOperation -> read-only preview; confirmFileOperation binds the accepted approvalScopeDigest and explicit Delete confirmation; applyFileOperation consumes the fresh plan. Host must retire/certify/forget the exact retained handle, reprepare, compare stable approval scope, then apply. Keep/move/relink do not change startup/force/manual pause fields. Only removal revokes Scheduler ownership. hasPendingFileOperation is conservative on ambiguity; startup calls recoverFileOperation before owner admission.

Scope: modern original inventory plus authenticated original linear layouts, up to 10,000 files and 64 MiB per original document. Nonlinear storage, external file links, unresolved completion journals, shared/overlapping payloads, symlinks and preexisting relocation targets are refused. Original flag 0x40 prohibits Delete. Metadata archives remain unchanged. Listed payload leaves alone are deleted; foreign files and empty directories remain.

Ordering: sync private confirmed-intent journal; publish every destination without overwrite (same-filesystem hardlink, or bounded exclusive copy+sync); publish sparse cache/state/inventory changes; remove source leaves; remove selected active state for removals; remove journal last. Before metadata publication both old/new roots retain data. Relink changes metadata and requires recheck without modifying either payload. Copy validates actual bytes. No blind retry/truncate of original data. Cancellation is accepted before journal creation only. Observer exceptions deliberately leave recovery pending.

Recovery: exact original hash/path/inode binding, private owned single-link journal with checksum, sparse target row/pause/cache comparisons preserve unrelated checkpoints. Changed target state, unknown scratch or unpublished/torn saving temporary remains an explicit conflict. Recovery does not promise autonomous repair of every torn write or hostile same-UID mutation. POSIX path checks cannot atomically prevent an uncooperative same-UID process swapping a name after its final identity check; caller holds exclusive profile lease and must exclude concurrent payload mutations.

Tests: five source-authored families cover keep/delete/foreign leaves, interruption before metadata with unrelated row/cache checkpoints, relink/recheck, live-preview rebase, cancellation, original protection/shared paths/symlinks/no-overwrite, and actual copy bytes with test-only EXDEV linkat injection. This is not a real cross-mount runtime result. No C++ build/test or Java execution by author. Separate original-reader driver is additive and follows this frozen implementation.
