# Directional shared tag backend

Original semantic baseline `cb8c6cb9bb97916cbc7e80338a017200ffc3e71f`;Native `cb42215fcd150c2fbb1e8e1bad8778654aa980be`,tree `15941470d56370012a408cb7a23704719280b9d4`.

An isolated SDK source delta adds session/class-owned upload and download prohibition masks. Masks combine across all current classes;removing one owner cannot cancel another. Upload guards both unchoking and incoming requests,including allowed-fast requests;download guards block selection. Current transitions cancel queued download requests,choke current upload peers and wake normal/local peers through the SDK's own accounting. Session abort clears policy. The patch does not change public C++ structures or virtual tables. It also removes the peer-class ten-byte floor,so positive1..9 values survive actual setters/getters. Zero remains unlimited and the signed infinity sentinel is refused. The public C interface requires actual live SDK pointers/allocated classes and its network thread;it is no profile permission API.

The Native shared-group owner uses the actual SDK context for atomic policy/class changes and completion fences outside filesystem gates. Exact readiness is published only after SDK getter verification and current-peer updates. A class without any torrent can close immediately;retirement clears masks before pool reuse and retains the existing deferred quota-pointer lifetime protection. Older providers continue to refuse disabled/tiny values explicitly. The saved-source/editor eligibility policies remain at their existing supported range until separate normal-runtime integration.

Seven generated actual-owner cases cover independent directional payload,independent owners,live detach,positive-to-disabled mutation on an established peer,exact tiny getter/readiness,anchorless close and class-slot reuse. Disabled initial directions transfer zero payload while the other direction progresses;unblocking completes both halves on the existing connection. Live mutation allows already-issued work to drain and then asserts no further blocked-direction progress before resuming. Tiny checks prove exact SDK getter/readiness values,not a long-duration one-byte payload timing guarantee. The existing two-torrent shared upload/download budget tests pass on both old and candidate SDKs;old representability and abort/readiness controls pass. The application builds against the unchanged qualified provider.

The first low-level fixture incorrectly accessed the incoming peer's torrent before SDK attachment;bounded SDK events identified this test-only failure. The corrected actual Native owner already obtains class ownership from its session. A second failure showed that exempt local peers require an immediate wakeup after prohibition removal because normal unchoke scheduling excludes them;the SDK notification handles that path. No live-client bug is claimed from the fixture failure.
