# Original Azureus node identities and regular UDP contacts review

Source baseline cb8c6cb9bb97916cbc7e80338a017200ffc3e71f. Exact original
DHTUDPUtils node/contact/array/address/length bodies, source constructor and
unchanged frozen SHA1Simple characterize the bounded native implementation.
The supplied transport/getters have empty position-provider state. No ordinary
core, transport, plugin, configuration, DNS or profile manager is initialized.
ReferenceFence is unchanged; generated fixture bytes are the only inputs.

The port preserves signed-byte thresholds32/33/50, IPv4 restricted decimal
identity keys, port moduli, Java uncompressed IPv6 spelling and numeric scope,
mapped-address factory normalization, the exact unresolved IPv6 seed-name hack,
and the128-entry access-order key history. The source reference runtime uses
UTF-8 Java17.0.20; qualified keys are ASCII. Scope-name discovery and arbitrary
platform default charsets remain outside this slice. Owned IDs deliberately
exclude accidental Java shared-array cache mutation. Native owner-thread
checking replaces shared global cache synchronization; no full source baseline
is advanced. OpenSSL3.5.5 EVP_Q_digest hashes keys, checks the exact20-byte result
and returns errors without inserting IDs when the provider fails.

Regular contacts preserve CT_UDP1/protocol/address framing, unsigned16-bit count,
source cursor consumption, mapped-address width and hashing before port0
filtering. Instance/skew/generic flags reset to zero on this wire path. A later
malformed contact retains earlier cache effects. Raw tails and IDs are owned.
Packet size is capped at8192; capacity is bounded by received bytes, avoiding a
65535-record allocation for a short hostile packet. Partial encodings remain
diagnostics. Decoded contact addresses are data and never become destinations.
