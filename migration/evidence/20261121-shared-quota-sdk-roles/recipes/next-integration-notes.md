# Next private tag-rate integration: inspected facts

Research only. No private admission,source capability or code has been ported here.

OwnedProfile::prepare is called on the external Host/I/O worker,before the QObject moves to its private Qt thread. It currently prepares first payload storage before creating the SDK session. Later SDK torrent installation occurs asynchronously on the private Qt thread after the bridge is ready. prepareTorrent/prepareMagnet remain on the recorded I/O worker. The origin and SDK consumer workers therefore have distinct roles after bootstrap;do not infer that every SDK group can be controlled from either thread.

OwnedI2pService::start and startPending wrap the entire prepare call in lease.sourceAccess. Both must release the filesystem gate before SDK construction/class waits,then revalidate the exact captured config/source before storage effects. ProfileSource already validates captured anchors and child snapshots within its own gates. Preserve the early active-private-rate refusal until an actual sealed complete cohort proof replaces it.

Required ordering: capture immutable source/config/policy;release FS gate;create actual SDK and per-role classes from the common origin;obtain actual class witnesses;reenter/revalidate exact source/cohort;prepare ManagedStorage;install actual paused handles;attach their exact classes on the class-owning worker;only then resume. Handle cancellation,source loss,partial attach,recovery and shutdown without an FS gate around SDK waits. D3 remote consumers can acknowledge only exact origin-published rates. Generic writers remain strict.

Mixed transport uses the existing normal Public handle/storage/session,not an extra payload owner. Verify this through the actual Host census. Dedicated private uses an explicit all-address global-class filter;its I2P loopback endpoints are not LAN. The existing Public LAN class filter and numeric proxy exception must remain. Global class0 and tags in any session must share the same allocator. The current Native quota wrapper uses raw logical tag IDs as SDK UIDs,so introducing a global UID requires an explicit collision-free profile namespace and source ID bounds;do not alias global UID1 with saved tag1. Source Original UID/type semantics must be characterized before that change. Existing CoexistCoordinator still statically divides rates and rejects tiny shared caps;replace it only after actual common owner/census qualification.

Candidate ABI2 DLL and all SDK role proof inputs stay frozen. The current selected ABI1 SDK,daily,real profile and payloads remain untouched. Continue after actual D5 Native checks and publication;do not stop at that checkpoint.

PreparedTagRateSource::matches is deliberately bound to the SAME actual ManualTagStore assignmentIdentity plus snapshot generation/lineage,source bytes,profile ownership and all SDK class witnesses. A separately opened private-source store cannot reuse that grant. Do not weaken this generic writer/CAS check. A dedicated private pre-storage target capability must separately seal the actual current source/hash and complete SDK cohort,with its own narrow consumer;or pass the actual existing store through a trusted owner path. Source proofs must retain neither a profile lease nor an FS gate.

SourcePermit owns a separate jthread which holds sourceAccess while Ready/Executing. OwnedProfile::startup installs SDK members inside that one-shot permit,then acknowledges it. Therefore a new private rate-attach callback must not reenter ProfileTagRates::prepare/attach source-reading paths on another worker while the permit worker holds the gate: that can deadlock. Actual private SDK class attachment should use already prepared,worker-owned SDK state with no filesystem access,or an explicitly staged gate-free handshake. Preserve the existing source authority lifecycle and cancellation/join guarantees.
