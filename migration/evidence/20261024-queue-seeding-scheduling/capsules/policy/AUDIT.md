Source-only assessment, original `cb8c6cb9bb97916cbc7e80338a017200ffc3e71f`.
The eight original plugin files are pinned in `original-pins.json`; immutable source copies are under `original/`.

The original plugin is a scheduler, not just two LT caps. `RankCalculatorReal` supplies rank, first priority, activity hysteresis and minimum runtime; `StartStopRulesDefaultPlugin` consumes those classifications in a stateful start/stop loop. The current native owner admits multiple handles and currently delegates automatic choice to LT with `active_downloads`/`active_limit`; force removes `auto_managed`, Pause holds the handle, Stop uses the certified flush/retirement/checkpoint path. This reducer cannot independently touch those mechanisms.

Original defaults and exact key mappings are in `catalog.json`. Important defaults: active4/download4/minimum1; ratio ranking1; FP Any1, ratio500 thousandths, time criteria disabled; ignore-zero true; modern FP-ignore-zero true (`ui=az2` makes default false); Stop Ratio0 unlimited; minimum seed300s and active-weighted900s; both active thresholds512 B/s; stalled seeds5 (configured0 becomes999 when threshold nonzero). The original default light-seeding enable=true/reserved4/flexible5 does not prove a native lightweight-seed provider.

Ranking and first priority:

- Modes0/1/2/3/4 are None/seed:peer/seed-count/timed/peer-count. Incomplete rank is1000000000+(10000-position). None still runs ignore tests first.
- Seed:peer uses Java binary32 x=seeds/peers and truncates99999/((x+1)*(x+1)). With no seeds, at least configured peers gives99999; otherwise0. Seed count is(10000-seeds)*100000 below10000, else100000; configured fallback switches to ratio at the inclusive threshold. Peer count uses100*peers*10 when peers>seeds*10, otherwise(long)100*peers*peers/(seeds+1), then Java int narrowing. Negative final ordinary rank becomes1. Native unsigned wrapping reproduces those source operations without signed overflow.
- Positive friend/tag FP precedes negative-tag FP; persistent/complete/not-stopped/not-error follows. Declared FP hooks are caller authority, never inferred from names or memberships. Ratio below min override/global500 is the first enabled criterion. Any succeeds on a match; All needs every enabled criterion. Seed/active durations use strict `< minutes*60`. Disabled time criteria are skipped. FP exclusions use valid known0 peers, integer seeds/peers threshold, or idle strictly `> minutes*60`, with seconds-seeding fallback if last-upload is unavailable.
- FP bypasses ignore rules. Otherwise priority order is share ratio(-8), valid zero peers(-7), seed count(-5), float peers/seeds threshold(-4). Infinity share ratio=-1 is not ratio-met. Per-torrent stats.min.share.ratio/stats.max.share.ratio override positive values only. No rankable scrape gives-9; native keeps the original no-scrape queue gate, even after startup90s. A successful tracker sample must prove self-exclusion with sample/start ordering; connected peer counts are not substituted.

Scheduling/activity boundaries:

- Forced downloads do not occupy queue slots; actively forced seeds do. Manual pause/stopped/error/retiring are never automatically resumed. Checking/preparing remain protected; ignore-checking removes checks from download slot counting. Queue is a non-retiring pause; user Stop remains the existing flush/checkpoint operation.
- Native plans select active downloads after FP/forced seed reservation but honor the minimum-download floor; configured0 maximum is unlimited. New admissions reserve a slot; confirmed stalled downloaders do not consume one. Seed ordering is FP first, rank descending, preferred swarm size, share ratio, saved position, then stable token. Incomplete order supports saved position, seed count/reverse, size/reverse, remaining and original file-stat indices1/3. Missing comparator inputs are ordered consistently as unknown rather than injected0.
- The original30s grace and10s transition hysteresis use explicit same-owner monotone time. Real disk latency>2500ms holds active for60s after the latest high observation. Missing latency is diagnosed; no artificial latency is supplied. Missing rate preserves prior classification but slot accounting remains conservative.
- A running seed cannot be queued before its supplied elapsed runtime reaches the minimum. Original300..900s weighting consumes actual smoothed torrent/global upload. If those contributions are unknown, native conservatively protects the900s maximum. Timed rotation consumes actual elapsed seeding and connected leechers and preserves the greatest derived timed minimum for that admission. No clock reads or timers exist here.
- Saturation uses observed source rates; upload-start prevention uses the original strict KiB comparison and95% default. Native aggregate-rate saturation is a bounded substitute for the original mutable within-cycle prefix totals, not Java scheduling equality. Stalled seeds are retained separately up to the configured limit; known zero peers may be exempt only when configured and source-valid.

Explicit remaining provider differences: lightweight/reserved seeding and flexible transient oversubscription; speed/ETA active probing; actual external FP hooks and tag-specific limits; automatic saved-position normalization/newly-complete pool movement; the plugin's independent stale-rank change-check timer. Inputs include an explicit stale rank offset, but this reducer does not invent that external timer's observations. These features cannot be credited from the ordinary scalar rank replay.
